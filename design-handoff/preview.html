The wallet, as tokens

Every value read from the Flutter source or measured off a device. Import the JSON into Figma with Tokens Studio, or hand it to Claude Design. Nothing here was taken from a mockup.

How to use it

The file is design-handoff/tokens.json in the wallet repo, in W3C DTCG format — the same shape Tokens Studio and Style Dictionary read. In Figma: Tokens Studio → Import → paste the JSON. In Claude Design: give it the file and it will build on these values. The full text is at the bottom of this page.

One caveat worth carrying across. These describe the wallet as built today, including two things that are open rather than settled: the BitFinite colour drift, and the Bellscoin accent failing on light backgrounds. Both are marked in the tokens themselves.

Screen structure

Tokens do not carry this, and a designer needs it: the wallet screen is one scrolling page. Only the app bar is pinned — it holds the back control, the wallet name and the menu, and it paints the hero surface so rows pass cleanly behind it. Everything below scrolls, including the hero.

Order down the page: hero (chart, balance, fiat, address chip) → payouts row, which renders only on a wallet that mining has paid → Transactions header → truncation notice, only when the history was capped → day header → transaction rows. The Receive/Send dock floats over the bottom and the last row pads itself past it.

Two conditional pieces are easy to miss when designing: the payouts row and the truncation notice. Both are absent on an ordinary wallet and present on a mining or exchange address, so the screen has two quite different heights.
